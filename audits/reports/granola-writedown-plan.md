## Method and execution boundary

Read `audits/reports/granola-batch-onhand-audit.md` before querying. Scope: `products.type='batch'` and name containing Granola. All ledger quantities come from `ledger_current_transaction_lines` joined to `ledger_current_transactions`, restricted to `effective_status='posted'`. Every database query begins with `BEGIN; SET TRANSACTION READ ONLY;` and ends with `ROLLBACK;`; the connection additionally sets `default_transaction_read_only=on`. Connection details are read from `~/.config/factory-ledger/db_url` and are never intentionally logged. The snapshot is current posted on-hand, consistent with the dashboard and the September 17 count.

Files: `scripts/granola_writedown_0917.py` and its frozen input `scripts/granola_writedown_0917_plan.json`. Running with no flag is identical to `--dry-run`. It checks fresh product/lot balances against the frozen snapshot, refuses drift or existing September 17 count entries, verifies FIFO/nonnegative balances, and checks both reason totals and every product target. It does not dynamically resize the plan. No API calls, key retrieval, or writes occur in dry-run.

**Named-actor prerequisite is unresolved.** The located September 15 precedent is `/Users/cns/Documents/Codex/2026-09-15/read-only-investigation-no-code-changes/work/apply-coconut-adjustments.py`, with companion `coconut-dry-run.py`. It uses per-lot `POST /adjust`, exact product codes, dated requests, balance preflight and receipt verification. However, it fetches the shared Railway `API_KEY`, expects `operator_id=legacy-shared-key`, and appends `Actor: Blubber.` to reasons. It is not a named-actor-key implementation. The current backend explicitly excludes `/adjust` from the named-actor allowlist and the handler has no named-actor attribution plumbing. No alternative September 15 named-actor script was found.

The new script retains the per-lot `/adjust` method but requires an active named key in `FACTORY_LEDGER_ACTOR_KEY` plus an explicit `--actor NAME` for any future `--apply`; it never falls back to the shared key or alters the exact requested reasons. It checks the key hash with read-only SQL, then checks API identity and previews all calls before any commit. With the current backend, the named-key preview is expected to fail authorization; **the apply path is not deployment-ready until named-actor support or the intended precedent is resolved**. No apply was attempted. A future apply must run with inventory activity paused because `/adjust` lacks an atomic expected-balance condition; its separate requests are not one atomic transaction. On any uncertain result it stops without retry, and a partial run requires reconciliation rather than replay.

The proposed effective timestamp is `2026-09-17T12:00:00-04:00`, a bookkeeping noon timestamp for the specified count date, not a claimed physical observation time. Vanilla Crisp and Dark Chocolate have no payloads. All HTTP activity, including `/auth/whoami`, is confined to explicit apply because actor authentication can update `last_used_at`.
