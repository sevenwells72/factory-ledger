# AI-assisted Expected Receipt intake (design, approved 2026-09-08)

Owner-approved proposal for creating expected receipts from a photographed or
PDF'd vendor PO / order confirmation. Amendments from the approval review are
folded in and marked **[A]** where they changed the original proposal.

## Goal & flow

User drops a PNG/JPG/PDF into the New Expected Receipt modal →
`POST /expected-receipts/extract` stores the file (Supabase Storage) and sends
it to a vision model with a strict JSON schema → `POST /expected-receipts/match`
deterministically matches supplier + lines to internal IDs → review screen shows
matches with confidence, unit→lb conversion, and a per-line product picker →
on approve, ONE expected receipt per line via the existing creation logic, all
in one transaction.

## Hard rules

* The model never writes to the DB. Extraction and matching are separate steps;
  `extraction.py` imports no DB code at all — the rule is structural.
* `supplier_product_aliases` is checked BEFORE any fuzzy match; rows are written
  on approval. **[A]** Latest approved correction wins (upsert, not first-write).
* Dedupe on supplier_id + normalized reference_number: warn + `force` override,
  never a hard block. **[A]** closed/cancelled ERs also appear in the warning,
  with their status.
* Source file stored in Supabase Storage, referenced on each created receipt
  via `expected_receipts.source_document_id`.
* Extraction lives behind `extract_purchase_document(file_bytes, mime_type)` in
  `extraction.py` so the API vendor is swappable in one module.
* **[A]** `/extract` and `/extract/approve` go through the same global readonly
  tripwire as all other writes (standard `get_transaction` + psycopg2.Error
  handler path — no bespoke error handling that would bypass it).
* **[A]** The tool-use schema must allow `null` for `reference_number`,
  `document_date`, `expected_delivery_date`, and line `unit`. Prompt rules:
  never guess missing values; return vendor descriptions verbatim.

## Vendor & infra

* Claude via the Anthropic API. Default model `claude-sonnet-5`, overridable by
  `EXTRACTION_MODEL` env var.
* Env vars on Railway (assumed present): `ANTHROPIC_API_KEY`, `SUPABASE_URL`,
  `SUPABASE_SERVICE_ROLE_KEY`.
* Private bucket `purchase-documents`; **[A]** created on first use if missing
  (Storage API, service-role key).
* File caps: 15 MB, PDFs ≤ 20 pages.
* New dependency: `anthropic` (brings httpx, which is also used for the Storage
  REST calls).

## Migration 049 (`migrations/049_purchase_doc_intake.sql`)

```sql
BEGIN;

-- One row per uploaded vendor PO / order confirmation. The raw validated
-- model output is kept in `extraction` for audit; it is never re-read by
-- any inventory or matching path after approval.
CREATE TABLE IF NOT EXISTS public.purchase_documents (
    id                integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    storage_bucket    text        NOT NULL DEFAULT 'purchase-documents',
    storage_path      text        NOT NULL UNIQUE,
    original_filename text,
    mime_type         text        NOT NULL
                      CHECK (mime_type IN ('image/png','image/jpeg','application/pdf')),
    file_sha256       text        NOT NULL,
    byte_size         integer     NOT NULL CHECK (byte_size > 0),
    extraction        jsonb,
    extraction_model  text,
    status            text        NOT NULL DEFAULT 'uploaded'
                      CHECK (status IN ('uploaded','extracted','extraction_failed','approved')),  -- [A]
    approved_at       timestamptz,                                                               -- [A]
    uploaded_at       timestamptz NOT NULL DEFAULT clock_timestamp(),
    created_by        text
);
CREATE INDEX IF NOT EXISTS idx_purchase_documents_sha256
    ON public.purchase_documents (file_sha256);

-- Supplier's wording → our product, learned on approval (latest wins).
-- Checked BEFORE any fuzzy match. lb_per_unit converts the vendor's unit
-- (case, bag, ...) to pounds.
CREATE TABLE IF NOT EXISTS public.supplier_product_aliases (
    id                 integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    supplier_id        integer       NOT NULL REFERENCES public.suppliers(id),
    vendor_description text          NOT NULL,
    product_id         integer       NOT NULL REFERENCES public.products(id),
    lb_per_unit        numeric(14,4) CHECK (lb_per_unit > 0),
    unit               text,
    created_at         timestamptz   NOT NULL DEFAULT clock_timestamp(),
    created_by         text,
    updated_at         timestamptz   NOT NULL DEFAULT clock_timestamp()
);
CREATE UNIQUE INDEX IF NOT EXISTS supplier_product_aliases_uidx
    ON public.supplier_product_aliases
    (supplier_id, lower(regexp_replace(btrim(vendor_description), '\s+', ' ', 'g')));

ALTER TABLE public.expected_receipts
    ADD COLUMN IF NOT EXISTS source_document_id integer
        REFERENCES public.purchase_documents(id);
CREATE INDEX IF NOT EXISTS idx_expected_receipts_source_doc
    ON public.expected_receipts (source_document_id)
    WHERE source_document_id IS NOT NULL;

-- Dedupe lookup (warn-only, no unique constraint).
CREATE INDEX IF NOT EXISTS idx_expected_receipts_supplier_ref
    ON public.expected_receipts (supplier_id,
        lower(regexp_replace(btrim(reference_number), '\s+', ' ', 'g')))
    WHERE reference_number IS NOT NULL;

COMMIT;
```

## Endpoints (all on DASHBOARD_KEY_ALLOWLIST; master key also works)

### 1. `POST /expected-receipts/extract` — multipart `file`

Validate type/size → sha256 → upload to Storage at
`YYYY/MM/<sha256[:12]>-<safe-filename>` → insert `purchase_documents`
(status `uploaded`) → `extract_purchase_document()` → store validated JSON,
status → `extracted` (or `extraction_failed` on model error; file + row are
kept so retry needs no re-upload).

`201 { document_id, storage_path, already_seen, extraction: { supplier_name,
reference_number, document_date, expected_delivery_date,
lines: [{vendor_description, quantity, unit}] }, extraction_model }`

Errors: 415 `UNSUPPORTED_FILE_TYPE`, 413 `FILE_TOO_LARGE`,
502 `EXTRACTION_FAILED` (includes `document_id` for retry).

### 1b. `POST /purchase-documents/{id}/extract` — retry

Re-runs extraction on the stored file (downloaded from Storage). Same response
shape as /extract.

### 2. `POST /expected-receipts/match` — JSON `{ extraction }`

Pure deterministic read; no LLM, no writes. Re-called by the dashboard whenever
the user changes the supplier.

```
{ supplier: { match|null, confidence: exact|fuzzy|none, candidates },
  duplicate_warning: { existing: [{id, status, expected_qty, created_at}] } | null,
  lines: [{ vendor_description, quantity, unit,
            match_source: alias|exact|fuzzy|none, confidence,
            product|null, candidates (≤5),
            lb_per_unit|null,
            lb_source: alias|unit_is_lb|parsed_description|case_size|kg|none,
            expected_qty_lb|null }] }
```

**[A]** Matching order per line: alias → exact/normalized product match →
strong fuzzy (`_tiered_product_search`) → *AI candidate selection stub* →
human. The stub is clearly marked, NOT implemented in V1: it receives ≤5
factory-ledger candidates and may only return one of their IDs or null —
it can never introduce a product outside the candidate list.

**[A]** lb conversion from the product master (`case_size_lb`,
`default_case_weight_lb`) is allowed only when `match_source` is `alias` or
`exact`. For fuzzy/none matches `expected_qty_lb` stays null until the user
confirms the product (the dashboard then recomputes/asks). Conversion order
where permitted: alias `lb_per_unit` → unit is lb/lbs → weight token parsed
from the vendor description ("50 LB") → product master case weight (alias/exact
only) → kg × 2.20462 → null (manual). The review UI shows `lb_source` next to
every computed value.

### 3. `POST /expected-receipts/extract/approve`

```
{ document_id, supplier_id, reference_number, expected_date,
  lines: [{ product_id, expected_qty_lb, expected_date?, vendor_description,
            quantity, unit, lb_per_unit, save_alias }],
  force: false }
```

One transaction: dedupe re-check (409 `DUPLICATE_REFERENCE` unless `force`) →
per line, `_create_expected_receipt_core()` (factored out of the existing
`create_expected_receipt` handler; both paths share validation/insert) with
`source_document_id` set and notes auto-composed
(`"PO <ref>: <vendor_description> — <qty> <unit>"`) → alias upsert where
`save_alias` (ON CONFLICT DO UPDATE — latest wins) → document status →
`approved`, `approved_at` stamped. Atomic; a bad line rolls back everything.
**[A]** No per-line HTTP calls from the dashboard.

`201 { created: [full ER records], aliases_saved, duplicate_overridden }`

### 4. `GET /purchase-documents/{id}/url`

Short-lived signed Storage URL for the review screen and the ER table
paperclip link.

## `extraction.py`

`extract_purchase_document(file_bytes, mime_type) -> dict` — Anthropic Messages
API, forced tool-use with the strict schema below, model from `EXTRACTION_MODEL`
(default `claude-sonnet-5`), output validated (Pydantic) before return. Raises
`ExtractionError` on refusal/invalid output/API failure. No DB imports.

Schema: `supplier_name: str`, `reference_number: str|null`,
`document_date: str|null (YYYY-MM-DD)`, `expected_delivery_date: str|null`,
`lines: [{vendor_description: str, quantity: number, unit: str|null}]`.

Prompt rules: extract only what is printed; never guess missing values (return
null); vendor descriptions verbatim (no normalization, no translation);
quantities as ordered (not shipped/backordered) when the document distinguishes.

## Review screen (dashboard)

Replaces the modal body after extraction succeeds; manual entry stays as-is
(dropzone is additive at the top of the current modal).

* Header: filename + view link (signed URL), supplier match with confidence
  badge + candidate dropdown (+ "create supplier" via existing POST /suppliers),
  editable reference #, document date, expected delivery date (prefills lines).
* Duplicate banner when supplier+reference exists (any status, shown with
  status); "create anyway" arms `force`.
* Per-line rows: vendor description (read-only), qty + unit (editable), match
  badge (Alias / Exact / Fuzzy n% / No match), product picker (reuses
  er-product-search typeahead), lb-per-unit (editable, source-tagged),
  computed expected lb (editable override, shows `lb_source`), include-line
  checkbox. Lines with no product or no lb value block Approve.
* Footer: "Approve — create N expected receipts" with total lb.

## Deferred

* **Session-based auth for the intake endpoints** (audit #1, finding 6). The
  dashboard key ships in the browser bundle, so any holder can upload
  documents, invoke/retry paid extraction, and mint signed URLs. Interim
  mitigation on this branch: per-key rate limits — extraction (upload + model
  runs) 30/hour, signed URLs 120/hour — returning a logged 429. Replacing the
  browser-distributed key with per-user sessions is deliberately NOT part of
  this branch; it belongs with the planned key-rotation work, where every
  dashboard endpoint moves off the shared key at once.
