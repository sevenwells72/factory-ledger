## What this run did

Every screen in the inventory was rendered against a local static server over `dashboard/`, with every
Railway API call answered from `tests/visual/fixtures/`. No network request left the machine and no
database was touched. Writes (`POST`/`PATCH`/`PUT`/`DELETE`) are acknowledged by the stub and applied
nowhere. Fixture dates carry `{{TODAY}}`-style tokens resolved once per run against the plant timezone,
so overdue flags, the rolling calendar, and "today" are correct on any run day while staying byte-stable
within the run — which is what the LAYOUT-020 before/after comparison depends on.

## What is and is not checked

Each rule below has one clause a rendered page can settle without judgement. The rest of each rule —
and every rule not listed — is untouched by this run and is **not** reported as passing.

| Rule | Clause checked mechanically | Method | Clause **not** checked here |
|---|---|---|---|
| **TOUCH-003** | Hit region ≥ 44 × 44 pt | `getBoundingClientRect()` on every visible interactive element in the screen's region, including the six non-control classes that carry click handlers (`.lot-link`, `tr.expandable`, `.order-row`, `.search-item`, `.product-lot-row`, `.supply-item-row`) | Visible hover / focus / selection states; glyph padding; neighbour overlap |
| **ACCESS-008** | WCAG AA contrast (4.5:1 body, 3:1 large) | Computed `color` composited over every translucent fill up to the first opaque surface, multiplied by inherited `opacity`; ratio per WCAG 2.x relative luminance. Rendered **placeholder** colour is measured too, through `getComputedStyle(el, '::placeholder')` — INPUT-022's clause | Colour-blind separability; increased-contrast mode; text over images; printed output (FEEDBACK-011) |
| **LAYOUT-003 / ACCESS-001** | No horizontal document overflow | `documentElement.scrollWidth − clientWidth`; offenders inside a genuine `overflow-x` scroller are excluded | Orientation change; Spanish label length; largest OS text size; hierarchy preservation |
| **LAYOUT-011** | Fixed bars do not cover the last scrollable row | Every scroll region driven to its end, then `elementFromPoint` occlusion probes. A candidate is only a failure if it is under a *bottom-anchored* bar at maximum scroll, or still occluded after being re-parked at 60% of the viewport — a row passing under a sticky header is reachable and is not counted | Whether the layout uses the available space |

| **STATUS-004** | At most one danger/warning-toned element per list row | Tone decided by hue against the resolved `--danger` / `--warning` tokens (±12°, saturation ≥ 0.22), counted per row. Inherited `color` counts once, on the element that introduces it | Whether the surviving alarm is the *most severe* of the conditions present |
| **STATUS-005** | The explanation hook exists | `data-explain` naming a real element, `aria-describedby` naming the same id, and a focus stop, on every chip. Chips whose only explanation is `title=` are counted separately | The explanation's **content** — definition plus this record's quantities, lines and dates. Manual |
| **STATUS-006** | One number format | Rendered numeric text: ≥ 3 decimal places, ≥ 1,000 without a separator, decimal pounds, pallets past one decimal, and digits in an aligned column without tabular figures. Codes, dates, bare years and any column whose header names an identifier (SKU, Code, Lot, Order) are skipped; the tabular clause is measured only where digit width can misalign a column — a separator, a decimal, a unit, or three or more digits | Whether the same quantity agrees between screen, print and export |
| **STATUS-007** | No orphan placeholders | Elements whose entire text is a dash, `n/a`, `none`, `null` or `undefined`, outside a table cell (a cell dash holds column alignment and is the rule's exception) | Whether omitting the line loses a distinction the reader needed |

| **STATUS-010** | No developer vocabulary | Denylist scan over rendered text and over `title` / `placeholder` / `aria-label`, plus any `snake_case` identifier. "returns" is not on the list: on a factory floor it means returned goods | Tone, jargon that is not on the list, Spanish copy |
| **STATUS-011** | A disclaimer appears once | Sentences of 40 characters or more, counted within one capture; any rendered twice is reported | Whether the one surviving copy sits at first relevance |

**One approximation, stated.** Where an ancestor sets `opacity`, the text colour is faded against its local
backdrop. That is exact wherever the faded subtree sits on the same surface as its backdrop — the
depleted-lots table at `opacity: 0.6` is that case — and a close approximation otherwise.

**Thresholds.** TOUCH-003 fails on any element under 44 pt in either axis. ACCESS-008 fails on any text
node below its AA target. LAYOUT-003/ACCESS-001 fails above 1 px of document overflow. LAYOUT-011 fails on
any occluded interactive element. LAYOUT-020 passes at CLS ≤ 0.1 **and** zero moved anchors, warns to
CLS 0.25, fails above it.
The STATUS rules fail on any single instance: one coloured nominal badge, one row with two alarms, one
chip without the hook, one mis-formatted number, one orphan dash, one row over 56 px, one denylisted term,
one repeated sentence.

**STATUS-005 checks the MASTER-defined `data-explain` hook.** The Sales Orders list implements it;
screens that have not yet adopted the hook still report failures, including chips that currently rely
only on a `title` tooltip that a touch device never shows.

### LAYOUT-020 — layout shift on refresh

**Read the trigger column before the CLS column.** Two different things were measured, and only one of them
is what LAYOUT-020 prohibits.

* **A real background timer fired** (0 captures): the Recent Entries 60-second poll, the
  Order Detail allocation-expiry countdown, and Process Flow's 60-second auto-refresh. These are exactly the
  case the rule is about — content changing with no user action. **0 of 0 recorded CLS 0 with nothing moved.**
  Process Flow keeps its last good render and rewrites in place; the countdown rewrites text inside a fixed cell.
  On the evidence of this run the product has no background refresh that moves content under the user.
* **The Refresh control was pressed** (9 captures), because those screens have no timer of their own.
  LAYOUT-020 permits layout change that is "a direct response to their explicit action", so a shift here is not a
  violation of the letter of the rule. It is reported because the same `refreshAll()` path runs unprompted at app
