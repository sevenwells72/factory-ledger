**Date:** 2026-09-08 · **Target:** https://cns-factory-ledger.netlify.app · **Branch:** `test/visual-audit`, based on `origin/main` at `feefa17`.

This report supersedes the previous local-fixture results in this file. It audits production with Playwright Chromium and WebKit. [Standards](../FL-Design-Standards-MASTER.md), [inventory](00-screen-inventory.md), and [master improvements](IMPROVEMENTS-MASTER.md) were read; the master list and all shipped assets are unchanged. ## Scope, provenance and limits

The matrix includes all 91 inventory IDs plus **S-92**, an audit-only ID for the later Needs Attention strip. Each has eight requested viewport/theme combinations per engine: **390×844**, **844×390** (phone landscape), **768×1024**, and **1280×800**, each light/dark. DPR is 1; these are CSS viewport tests in desktop engines, not physical phone emulation. Print-only S-71/S-91 use print media at the same dimensions. A surface without a light palette remains its native palette; requesting light does not create one.

There are **1472 matrix records**, **1472 screenshot paths**, and **1172 successfully reached/measured screen variants**. 300 records are unavailable-state context or harness errors; these are explicitly U. **A context screenshot is not a claim that an inaccessible dialog, populated table, or error state was captured.** See the coverage table. Every screenshot and raw result is committed under [live-evidence](live-evidence/).

The initial smoke/concurrent attempts encountered production HTTP 500 responses with “connection pool exhausted.” They were stopped. The retained run reuses loaded pages and serializes API reads across engines, forwarding genuine responses unchanged; it uses no fixture responses or data cache. Preliminary captures were superseded by the final harness revision. API timing in this arrangement is not a performance benchmark.

Production differs from the branch baseline in **8/9** sampled assets. [Asset hashes](live-evidence/assets.json) identify the observed deployment; they do not prove a single immutable deployment for the entire audit window. No production change is attributed to this branch. The application loaded without a login, using its existing configured authentication. Credentials, headers, request bodies, query strings, and browser storage were not written to evidence.

[Safety observations](live-evidence/safety-observations.json) retain two discovery POST-preview requests blocked before transmission, and explain the guarded implicit Allocate activation generated by Enter. These are not successful submissions. S-39 is recaptured as an unavailable preview under this GET-only policy.

The harness never deliberately clicks Save, Post, Receive, Pack, Ship, Void, or any other commit control. It blocks non-GET/HEAD/OPTIONS requests, mutating paths and form submission before application handlers; native dialogs are dismissed. Modal drafts are cancelled. The scheduler uses a disposable context with its default local state; no sample orders, imports, baseline, or user scenario is created. [Guard test](../../../tests/visual/live/safety.test.mjs) verifies that the forbidden controls and network writes are intercepted on a synthetic data document.

## New proposed findings

### VA-001 — Keep primary-button hover text above AA in dark mode

**Status:** proposed — not yet in master list

**Rules:** ACCESS-008 (Critical, Hard rule) · ACTION-002
**Screens:** S-33 (observed) · **Importance:** Critical · **Effort:** S

With an editable live order open at 1280×800 in dark mode, hovering **Save Header** changes its background to `rgb(96,165,250)` (`#60a5fa`) while its 13 px normal-weight text remains white. Axe measures **2.54:1**, below the 4.5:1 target. The button was hovered, never clicked. The [dedicated hover screenshot](live-evidence/hover-S-33-dark.png) and [measurement](live-evidence/hover.json) capture the settled hover state.

IMP-010 covers the normal primary fill/text token split, but does not name this hover-fill contrast failure. Production has changed the normal dark fill while retaining the failing hover fill, so verifying the resting state does not close this case. This is an additional state-specific proposal related to IMP-010, not a claim that its prior normal-state findings are new. Scope is the observed button; other users of the hover token need checking.

**Fix (proposed only):** choose a hover fill that keeps white text at ≥4.5:1, and verify resting, hover, focus and pressed states in both themes. No implementation was changed.

### VA-002 — Make the first Activity collapse click update the panel

**Status:** proposed — not yet in master list

**Rules:** ACTION-002
**Screens:** S-17, S-18 · **Importance:** Medium · **Effort:** S

Both Activity panels initially render expanded. The first header click leaves the expanded class and visible searchable contents unchanged; a second click collapses the panel. The [recorded before/after classes and find counts](live-evidence/find.json), [Shipping screenshots](live-evidence/find-S-17-expanded.png), and [Receiving screenshots](live-evidence/find-S-18-expanded.png) document the live state. This is distinct from IMP-052’s find-within-page discoverability issue.

**Fix (proposed only):** initialize the expansion model from the rendered initial state, so the first activation collapses and updates its visible state. No implementation was changed.
