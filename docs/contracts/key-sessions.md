# Pilot sign-in: personal key → FL session

Implements design rev 3.8 §4.4 and §11 items 32–40 identity decisions. Codex builds; Claude Code reviews. #96 stays parked, with no dependency on migration 073 or its PIN routes.

`KEY_SESSIONS_ENABLED=1` enables `POST /auth/session {actor_key}` independently of `PIN_LOGIN_ENABLED`, which stays 0. Default/unset is off: exchange/logout return 404; existing shared/actor-key authentication and write behavior are unchanged, even with no pilot tables. Public `GET /auth/session/config` returns only the flag and 180-minute duration, with no-store.

Exchange accepts only a currently active personal actor key, refusing both shared keys even if their hashes appear in actors. It returns `{session_token,key_kind:"session",actor:{id,name,role},expires_at,idle_minutes:180}`. Tokens are 32 random bytes with an `fls_` prefix. Only SHA-256 hashes are persisted in `key_actor_sessions`, together with the issuing personal key hash. Personal keys remain usable by server clients and scripts. A personal key whose string begins with `fls_` still resolves as an actor key.

Send the token in `X-API-Key`. User-initiated authenticated session requests slide last_seen/expires_at by 180 minutes. Automatic reads (including polling and restored-page reads) send `X-FL-Background: 1` and authenticate normally without changing either timestamp. The marker never bypasses expiry, revocation, role or permission checks. At or after expiry it returns 401 `SESSION_EXPIRED` and persists `ended_reason=idle`. Explicit `POST /auth/session/logout` ends the token as `logout`; subsequent prepare/commit/Assistant Record is refused. Each token request reads the live actor and current key hash: deactivation or rotation refuses all old-key sessions immediately, persisting `revoked` on detection. This bypasses the legacy actor cache. Sessions inherit current roles and attribution. Internal permission/ticket identities normalize to the person so a new session for the same person may commit their unexpired ticket; another person cannot.

Tickets retain their existing 10-minute Assistant/30-minute dashboard expiry. No session operation extends a ticket. Expired tickets require prepare again; logout/idle never grants another actor access to a saved draft. Notes made with sessions append person attribution in the existing atomic actor_write_audit; legacy note behavior is unchanged.

Exchange is serialized across workers with a transaction advisory lock and persistent key_session_attempts. Limits: 10 attempts/minute per ASGI peer, five failures/15 minutes per peer, 50 failures/hour globally. Both success and failure attempts count; forwarded headers do not create app-level buckets. A 429 includes Retry-After. The global ceiling remains effective if Railway peers are proxies; trusted proxy configuration must be reviewed before rollout. No raw key/token/IP is persisted in attempts or printed; validation errors suppress credential-bearing input.

The Assistant clears the key field as the exchange starts, holds/saves only the session token in sessionStorage, restores identity/chat on reload, shows Signed in as and Sign out, and re-asks after expiry. Flag off retains its current per-tab actor-key flow. Dashboard and Runs requests use the personal session when signed in; automatic reads carry the background marker and do not keep the session alive. Explicit refreshes, navigation controls and writes count as user activity. Separate origins have separate browser storage; switching between Netlify and Railway requires signing in on that origin. Configuration failure blocks sign-in/saves instead of falling back to raw-key custody.

Migration 077 adds private RLS-on/policy-free key_actor_sessions and key_session_attempts, relaxes the existing audit target CHECK only to add notes, and appends a marker. It does not alter parked actor_sessions, actors/PIN columns, existing tickets or ledger rows. Applied only to staging in this build.

Acceptance: 2,526 Python/82 Node tests plus actual Chrome passed; hosted staging Arturo receive RCV-261013-005 recorded 10 lb once with person attribution. PIN off, four synthetic people exchanged keys; logout/idle/revocation passed. Temporary actors inactive. Evidence: docs/validation/key-sessions-staging.json.
